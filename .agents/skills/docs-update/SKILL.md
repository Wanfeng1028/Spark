# 文档变更流程

**触发**：修改本仓库任何 .md 文档（README.md / AGENTS.md / DESIGN.md / ARCHITECTURE.md / doc/*）。

## 步骤

1. **改内容**：先读目标文档与相关联文档，确认改动不与其他文档冲突。
2. **版本记录表追加**：目标文档开头的版本表追加一行，版本号 +0.1（大重构可 +1.0）。
   - 作者格式：AI 编写写明软件与模型（如 `ZCode CLI · GLM-5.3（builtin:zai-start-plan/GLM-5.3）`）；人类作者写名字；用户决策的注明"决策：晚风"。
   - 人类作者发起/审核的 AI 修改，两方都写。
3. **交叉引用同步**：若改动涉及文件名/章节号/结论变化，`grep -rn "旧引用"` 找出所有活引用并更新（版本记录中的历史行**不改**——那是历史）。
4. **单一来源检查**：确认没有把某条规则复制到第二个文件（应引用而非复制；见 AGENTS.md 规则放置规范）。
5. **提交**：conventional commits + 中文描述，正文列变更文件与要点。
6. **推送**：`git push origin main`；网络失败时用后台循环重试（45s 间隔，≤10 次）。
7. **多会话防冲突**：若检测到工作区有非本会话的未提交修改，先 `git pull --rebase`，版本号如撞号则合并重排（保留先来者版本号，后来者顺延），在提交信息注明。

## 禁止

- 跳过版本记录直接提交。
- 重写版本记录历史行（勘误除外，且需新增行说明）。
- 同一规则在多文件各写一份。
